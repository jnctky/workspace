⚠️ 邮箱域名**不能**用 `.local` 等保留域存库：`/pro/login` 返回体里的 email 过 pydantic

## 四点五、数据后端连接（2026-10-20 已接通）

Workspace 的数据来自「Connections」（即提供 `apps.json`/`widgets.json` 的后端）。
**本机 OpenBB Platform API（`openbb-api`，127.0.0.1:6900）原生就提供这些元数据**
（39 个 App、971 个 widget、agents.json），已通过接口注册为连接：

```
POST /pro/data-connectors/api-source/<uuid>   # name=OpenBB Platform (local 6900), url=http://127.0.0.1:6900
```

实测结果：
- Apps 页出现全部 39 个应用（BLS 全家桶、Cboe、CFTC、ECB、EIA、Fama-French、各地方联储、SEC、Treasury 等）
- 打开 "Cboe Market Data" → SPY 期权 IV 期限结构 / Open Interest 图表**真实出数**
  （`GET /api/v1/cboe/options/term_structure?symbol=SPY...` → 200，见截图 `my_tools/_tmp/cboe_app.png`）
- 6900 的 CORS 是 `access-control-allow-origin: *`，前端跨域无障碍
- 免密钥可用的源：Cboe、Nasdaq（部分）、BLS、SEC（需 UA）等；FRED/EIA 等仍需在
  OpenBB 侧配置 API key（`~/.openbb_platform/user_settings.json`）后重启 openbb-api

注意：重装/重置数据库后连接会丢，重跑上面那个 POST 即可；6900 服务要先于使用启动。

## 七、安装过程中的坑（复现时必读）

1. **npm install 直接崩**：`Cannot read properties of null (reading 'edgesOut')`。
   解法：`npm install --legacy-peer-deps --registry=https://registry.npmmirror.com`。
   首次正常安装后第二次重跑时已带此参数。
2. **peer 依赖缺失导致构建失败**：`react-vega` 需要 `vega-embed@^7` 但 package.json 没声明，
   已 `npm install vega-embed@^7 --legacy-peer-deps` 补装（写进了 package.json，属本地改动）。
3. **vite build 清空 dist 被沙箱 shim 拦截**（node-safe-delete-shim）：
   build 前手动删掉 `dist/` 即可绕过。
4. **后端依赖**：poetry 格式 + `package-mode=false`，无法 `pip install -e`。
   已用脚本从 `poetry.lock` 提取 47 个精确版本生成 `my_tools/requirements.txt` 后 pip 安装
   （含 git 依赖 slowapi@master，走本机 10808 代理编译成功）。
5. **Python 必须 3.13**（`python = "~3.13"`），用的是受管 3.13.14。
6. **Redis 是硬依赖**：Settings 与 RQ 队列启动即连接。本机原本没有，已下载
   redis-windows 8.10.2 便携版放进 `my_tools/redis/`。**bash 环境下 redis-server 会静默退出，
   必须用 PowerShell 启动**。
7. **建表要手动跑迁移**：SQLite 模式下 `init-db.py` 会跳过，需执行
   `python -m alembic upgrade head`（已在 backend 目录跑完）。
8. **curl 本地端口必须加 `--noproxy '*'`**，否则被会话代理拦成 502。
9. **密码强度有三道关**：① 前端 zod 校验（`src/utils/zodForms.ts` 的 passwordRegex）；
   ② 后端 `/login`、`/pro/login` 的 `check_password`（`api/schemas.py`）；③ bcrypt 存储。
   为了支持 `123456` 这类弱密码，①② 都加了本地放行（见第七节改动清单）。
   ③ 层用 `my_tools/create_guest_user.py` 直接写库绕过。
10. **`/pro/login` 要求用户挂 entity**：`guest` 登录返回的 entity 是迁移自带的
    "OpenBB Developer"（`entity` 表预置了 2 条），无需手动建。
11. **onboarding 卡跳转**：`needsOnboarding` 要求 `developer_onboarding` 表里有该用户记录
    且带 `role`+`organization`（或 `skip_onboarding=1`，但 developer 档位会被后端强制改回
    false，见 `routers/pro/index.py` 529-537）。建号脚本已写入该记录。

## 九、已知问题（上游快照自带，未修复）

   schemas 与 models 漂移，属快照质量问题。**已用 `create_guest_user.py` 直写数据库绕过。**
2. TradingView 图表资源 `/assets/js/datafeeds/udf/dist/bundle.js` 404（快照未含该 vendor 文件；
   仅影响 trading_view 小部件，主界面不受影响）。
3. AI 功能（`VITE_AI_API_URL`）本地无部署，不可用。
4. `run.py` 用 gunicorn + `resource` 模块，仅 Linux；Windows 一律用 uvicorn 直起。
